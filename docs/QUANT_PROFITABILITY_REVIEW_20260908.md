## 0. 2026-09-10 运营授权修订

> 本节记录所有者在阅读 09-08 审查与 AutoHedge 系统性对照后的运营决定。  
> **09-08 的证据判断不撤销**：系统仍不能证明已形成可持续盈利能力；账本、对账、同口径策略仍是 P0。  
> 本节只改**以后怎么跑两条线**，不把目标写成已验证能力。

### 0.1 两条线 = 同一策略、同一方案，只有资金和执行不同

**09-10 硬约定：研究线与真钱线不是「大组合实验室 vs 浓缩实盘」。它们跑同一套票组周期、同一 Mandate、同一候选与同一只数；差别只是本金和成交方式。**

| | 研究线 | 真钱线 |
|---|---|---|
| 策略 / 方案 | 与右列完全相同：§0.2 周期票组 | 与左列完全相同 |
| 资金 | 100,000 元模拟 | 30,000 元真实 |
| 执行 | 次日开盘**自动模拟成交** | **人工**买卖，收盘回填 |
| 账户 | `research_sim_100k`（或其后继） | `live_manual_10k` 升级为 30k |
| NAV | 永不与真钱合并 | 永不与研究合并 |
| 用途 | 同策略的干净对照：规则是否被执行、费用/整手/滑点差多少 | 真钱成绩单；人工偏离单独记账 |

因此：

1. **同一 Mandate、同一票组、同一只数、同一失效条件、同一 T0/M1/M2/T_end 日历**；
2. 金额按资金等比缩放：T0 部署约 **2/3**、现金约 **1/3**，单票硬下限仍是 3,000 元（两条线都适用）；
3. 研究线不得继续每日 TopK50 换仓来「代表」真钱；真钱也不得另搞一套 TopK7。旧 TopK50 只作为 09-08 的历史回测证据，不是 09-10 之后任一条线的生产策略；
4. 两条线收益差 = **执行差距**（人工延迟、未成交、最低佣金、整手取整），不是策略不同；
5. 分析 Agent / overlay 仍不得直接改订单；计划外成交进 `manual_override_book`。

当前配置差距（截至 09-08 代码）：研究线仍是 100k / TopK50 每日换仓；真钱线仍是 20k / TopK7。二者都还不是 §0.2，需要以后改配置（本次不改代码）。

### 0.2 共同方案：60 日票组周期

两条线都不再按「每日排名进出、持有约 10 日」验收，改为同一套周期组合。日历与规则相同，**只把金额按 100k / 30k 缩放**。

```text
每个周期约 40 个交易日（日历 1—2 月），两条线同一天切段：

T0  建仓日
    同一份逐票 CaseFile → 同一票组（推荐 4—5 只，硬约束见下表）
    买入约 2/3 资金；现金留约 1/3
    单票实际成交额 ≥ 3,000 元，否则该票两条线都不进组

M1  持仓第一个月（约交易日 1—20）
    只根据预先写明的失效条件调整票组（两条线同一调整名单）
    1/3 现金默认不打满
    允许减仓/换票，须写原因代码；禁止清单外标的

M1→M2  剩余约 1/3 逐步投入
    只加到当期仍有效的标的或已批准替补
    不合格则继续持现；不以满仓率为成功指标
    单票加完后仍须 ≥ 3,000，且建议不超过该线总资金的 20%

T_end  满约 2 个月
    两条线同一天周期结算，各出成绩单（金额不同，字段相同）
    再根据同一分析生成下一期票组
```

资金结构（同一比例，两条线各算各的）：

| 项目 | 研究线 100k | 真钱线 30k |
|---|---:|---|
| 总资金 | 100,000 | 30,000 |
| T0 部署（约 2/3） | 约 67,000 | 约 20,000 |
| T0 现金（约 1/3） | 约 33,000 | 约 10,000 |
| 单票硬下限 | ≥ 3,000（两条线相同） | 同左 |
| 推荐只数 | 与真钱相同，4—5 只 | 同左（由 30k 的 3k 下限约束：T0 最多 6 只） |
| T0 等权 5 只时单票 | 约 13,400 | 约 4,000 |
| 单票建议上限（总资金 20%） | 20,000 | 6,000 |
| 执行 | 模拟次日开盘 | 人工 |

只数由**更紧的那条约束**决定——真钱 30k + 单票 3,000 使 T0 最多 6 只。研究线不得因此改成 15—50 只；否则又变成两个策略。高价股在 30k 上整手后不足 3,000 或超过建议上限，则**两条线都跳过该票**。

### 0.3 月度 +10% 如何记录（必须读）

所有者希望「流程能不断成长，每月成本后 +10%」。本修订**接受它为 stretch 目标**，**拒绝把它写成保证或已验证门禁**。

算术约束：

- 30,000 元账户月 +10% = 当月约 +3,000 元净值；
- T0 只部署 20,000 时，现金约 33%。若目标按**总 NAV** 计，20,000 元票组当月约需 +15% 才能拉动账户 +10%；若目标按**已投资本金**计，则账户 NAV 约 +6.7%。验收时必须写明分母，默认分母为**总 NAV 的成本后 TWR**；
- 一年若每月 +10% 且再投资，约合 213% 年化；简单相加亦为 120%。现有 Alpha158 + LGBM 的研究证据是样本内年化超额约 11%（且测试段已用于调参），真钱污染账本全期 TWR 约 +3.44%。**没有任何 A/B/C 级证据支持「每月 +10% 可保证」**；
- 往返成本：3,000 元单票一次买卖固定税费约 0.38%+，加滑点约 0.5%—0.8%。60 日周期换一次整组，成本拖累远小于每日短线，但仍会吃掉薄 Alpha。

因此成长闭环的正确表述是：

```text
每个 60 日周期结束时必须能回答：
  1. 票组规则是否被执行（对账、人工偏离）
  2. 成本后 TWR 是多少（总 NAV 与已投资本金各一列）
  3. 盈亏来自哪些票、哪些决策（建仓 / M1 调整 / M2 加仓）
  4. 哪些规则下周期该改、哪些不该改（禁止用同一周期既交易又调参）

「保证每月 +10%」不是系统能力。
允许的产品语言：目标区间 / 历史可达性 / 失效条件。
禁止的产品语言：保证、必涨、稳赚。
```

前若干周期的毕业条件应是：**账本干净、规则被执行、成绩单可复盘**。月度 +10% 只作为观察指标；连续达不到不自动加杠杆，连续达到也不自动取消现金缓冲。

### 0.4 成长闭环：周期如何反哺模型与策略

这是「系统性」落地到双线上的方式：两条线同一周期、同一票组；研究线模拟成交，真钱线人工成交。差异只用于诊断执行，不用于改策略。

```text
周期开始
  一份 Mandate（本期问什么：风格、行业、持有期、禁止项）
  → 一份逐票 CaseFile
  → Risk 硬过滤（3k 下限、权限、ST；金额按各线资金缩放）
  → 同一票组清单
  → 研究线模拟下单 + 真钱人工下单

周期中
  只允许预先写明的调整，且两条线名单相同
  预测/观点到期进入 Agent 账本（分析产品，仍不改订单）

周期结束
  两份金额不同、字段相同的成绩单
  → 先拆：规则内盈亏 vs 人工偏离 vs 未成交/滑点
  → 再决定下一期 Mandate（禁止用同一周期既交易又调参）
```

禁止：

- 用 swing_hunter 的 LLM `predict` 直接当买入指令；
- 周期中途看见某票涨了就扩大宇宙、改门槛；
- 研究线改成 TopK50、真钱另跑 4 只——那是两个策略；
- 把研究线净值贴到真钱报告里当「本月 +10%」。

### 0.5 每个周期必须产出的成绩单

最少字段：

```text
cycle_id
start_day / end_day
mandate_hash          # 本期规则与禁止项
book_id               # research_100k_cycle 或 live_30k_cycle（策略相同，账本隔离）
nav_start / nav_end
twr_total             # 总 NAV，成本后
twr_deployed          # 已投资本金，剔除主动持现
cash_drag
fees / turnover
n_names / min_fill_amount / max_weight
fills_explained       # 对账无未解释差异
manual_override_count
per_name: 入场价、出场价、持有日、贡献、是否 M1 替换、是否 M2 加仓
failure_conditions_hit
next_cycle_proposal   # 继承哪些票、废弃哪些规则、待验证假设
```

未完成成绩单，不得开始下一期建仓。

## 1. 一页结论

### 1.1 总判断

项目已经具备较完整的量化研究和半自动交易闭环：

`数据 → 特征/模型 → 信号 → 独立复演 → 组合与订单 → 成交回填 → 对账 → 净值 → 看板`

分层思路、低换手意识、样本外门禁、研究与实盘双线、LLM 不直接生成交易数值等设计方向是正确的。核心 Alpha158 + LightGBM 策略也具有值得继续研究的历史证据。

但截至本次审查，系统尚不能证明已经形成可持续盈利能力。主要原因不是缺少更多预测模块，而是：

1. **研究策略与实盘策略不是同一策略**：回测为 TopK50、单票约 2%；实盘配置为 TopK7、单票上限 20%，当前实际持仓又达到 12 只并包含策略外 ETF。
2. **“测试集”已被多次用于选标签、持有期和 Plan C 参数**：IR 1.05 是开发过程中筛选出来的历史表现，不能再视为完全未触碰的最终样本外证据。
3. **实盘账本受到缺日、未成交、计划外成交、人工补仓和外部持仓注入污染**：收益无法清晰归因到模型。
4. **小资金真实成本明显高于研究假设**：实盘费用/成交额约 0.354%，约为研究模拟线的 1.75 倍；最低 5 元佣金是重要拖累。
5. **退出和组合级风险机制不完整**：主要依靠排名退出、最低持有期和单日熔断，缺少经验证的单票风险退出、组合回撤降仓和持续冷静期。
6. **执行正确性仍是 P0 问题**：48 份实盘对账报告中 33 份有差异；这会使“模型是否有效”与“是否按模型执行”无法分开。

### 1.2 对“终极目标：盈利”的直接回答

09-08 原文把盈利理解为 2—10 个交易日短线。09-10 授权改为：**研究 100k 与真钱 30k 跑同一套 1—2 月票组周期，只是资金与成交方式不同**（详见 §0）。短线涨停仍可研究，但必须另开 shadow，不得改写这两条主线。

这不改变基本纪律：盈利不是每天交易，也不等于看到涨停就追，更不是「保证每月 +10%」。可实现净收益仍是：

`可实现净收益 = 稳健 Alpha + 合理 Beta - 费用 - 滑点 - 现金拖累 - 执行偏差 - 系统错误 - 人工偏离`

在 09-10 授权下，当前最有价值的工作顺序应是：

1. **恢复真钱账本和执行的可信度**（否则新周期无法归因）；
2. **两条线改成同一策略、同一票组、分 NAV**，停止研究 TopK50、真钱 TopK7 这种「看起来像双线、实际是两个策略」；
3. **真钱按 §0.2 启动第一个 60 日票组**：T0 买约 20k、留 10k 现金，单票实际成交 ≥ 3,000 元；
4. **每个周期结束必须出成绩单**，用成绩单驱动下一期规则，而不是盘中改门槛；
5. **冻结最终测试集**，停止用同一测试段继续挑参数；
6. **月度 +10% 只作 stretch 观察指标**：分母用总 NAV 成本后 TWR，并另列已投资本金收益与现金拖累；
7. 首板次日确认等短线模块继续走独立 shadow，不与 30k 主周期混账。

当前建议：**立即按「同一方案、两份资金」运营；现有 swing_hunter 仍不能直接接入订单；未完成对账与子账本之前，两条线都不要把 1/3 现金提前打满。**

## 2. 审查范围与证据等级

### 2.1 审查对象

- 系统与业务文档：`README.md`、`PRODUCT.md`、`设计实现方案.md`、`quant/README.md`

- 运维与产品：`quant/ops/`、`quant/webapp/`

- 运行数据：`quant/data/accounts/`、`quant/data/reports/`、`quant/data/logs/`
- 当前未提交的板块预测设计：`quant/overlays/sector_forecast/`

### 2.2 证据分级

- **A 级：真实成交/账户证据**——fills、holdings、account.json、券商人工回填。
- **B 级：在线模拟证据**——research/shadow 账户按规则生成的成交与净值。
- **C 级：事件驱动历史复演**——Backtrader，包含整手、费用、停牌、涨跌停和滑点。
- **D 级：研究回测**——Qlib 向量化回测。
- **E 级：文档声明或 LLM 判断**——只能用于形成假设，不能用于证明盈利。

任何晋升和扩仓决策都应优先使用 A/B/C 级证据，不能用 E 级证据覆盖账本事实。

## 3. 系统与业务分析

### 3.1 现有业务定位

项目实际包含两个相互关联但应保持独立的产品；09-10 起交易运营内部再拆成两条资金线（§0.1）：

1. **量化交易运营系统**
   - 生成**一份**信号、票组和订单（金额按账户缩放）；
   - 研究线 100k 自动模拟成交；真钱线 30k **人工执行同一清单**；
   - 回填成交、对账和计算净值；
   - 目标是把可陈述规则转化为真实成本后收益，并用周期成绩单迭代规则。

2. **量化分析 Agent / 建议系统**
   - 预测账本、行业预测、舆情、短线猎手、持仓分析、逐票 CaseFile；
   - 目标是生成可结算观点，并在 T0 / 周期中段为票组提供证据；
   - 原则上不应直接改变核心订单。

这两个产品共享数据，但成功指标不同；交易运营的两条资金线也不可互相替代：

| 产品 / 资金线 | 第一成功指标 | 不能替代它的指标 |
|---|---|---|
| 研究线 100k | 与真钱同一周期的成本后 TWR（模拟成交） | 不能代替真钱、不能改成 TopK50 来「看起来更好」 |
| 真钱线 30k | 同一周期的成本后 TWR、对账、人工偏离 | 研究线净值、未结算荐股 |
| 两线跟踪偏差 | 同票组下的收益差（执行差距） | 把偏差解释成「该换策略」 |
| 分析 Agent | 到期可结算准确率、校准度、样本量 | 单次推荐是否碰巧上涨 |

### 3.2 现有系统的优点

1. **分层边界清晰**：研究、验证、执行和运维主要通过文件契约连接。
2. **低换手是明确的一等目标**：已经认识到高换手会吃掉 Alpha。
3. **Qlib + Backtrader 双引擎验证**：比只做向量化回测更可信。
4. **研究模拟线与实盘线分离**：具备测量执行偏差的基础。
5. **LLM 大多后置**：行业简报、舆情记忆和看板原则上不直接写模型数值。
6. **具有事故复盘意识**：代码中保留了日历卡死、现金闲置、熔断误触发等事故背景。
7. **Agent 预测开始采用可结算账本**：这比不可证伪的荐股文本更专业。

### 3.3 业务层主要问题

#### P0：核心产品边界被实际运营打破

当前实盘账本混入了：

- TopK7 系统选股；
- 人工未成交和计划外成交；
- 外部注资；
- 2026-09-03 直接补录的股票与 ETF 持仓；
- 舆情后的人工选择；
- 与回测不同的板块权限。

因此目前展示的“实盘收益”是**账户收益**，不是**核心策略收益**。

建议建立三个明确子账本（09-10 起真钱线每个 60 日周期都要能按此拆开）：

1. `system_model_book`：只接受当期票组清单内的系统订单和可追溯成交；
2. `manual_override_book`：所有人工加减仓及其理由（含计划外标的、提前打满 10k 现金）；
3. `external_or_legacy_book`：ETF、旧持仓、资金划转和非策略资产。

总账户 NAV 可以聚合展示，但策略验收只能看第一个账本。09-10 新周期开始前，应对 09-03 补录等存量做一次「遗产归入 external」或清仓重置，避免把旧污染带进第一个 60 日成绩单。

#### P1：功能扩张快于核心闭环成熟度

舆情、短线猎手、大盘看板、持仓追踪、Agent 和行业预测提升了分析覆盖面，但核心执行链仍有较高对账差异率。系统当前最稀缺的不是更多信号，而是：

- 可归因的净值；
- 不重复、不漏单、不串单的状态机；
- 同口径回测与实盘；
- 独立验证纪律。

建议未来 90 天将新增功能预算压低，把主要精力投入“正确性、归因和门禁”。

## 4. 架构与代码设计分析

### 4.1 架构总览

| 层 | 主要模块 | 判断 |
|---|---|---|
| L0 数据 | `data_pipeline` | 主路径+增量回退合理，但版本、PIT 和质检覆盖仍需加强 |
| L1 因子 | `factor_lab` | 门禁方向正确，需嵌套验证和冻结最终测试集 |
| L2 研究 | `research` | 基线清晰，但模型晋升和信号版本应显式固定 |
| L3 验证 | `validation` | 独立复演有价值，微观规则和 purge/embargo 不完整 |
| L4 执行 | `execution` | 功能齐全，但状态校验、现金/持仓不变量和测试不足 |
| L5 运维 | `ops`/`webapp` | 能运行，但调度与展示耦合、任务互斥和安全边界偏弱 |
| Overlay | `overlays` | 定位大多合理，不能阻塞核心订单链 |

### 4.2 P0：执行账本缺少必须成立的不变量

`quant/execution/record_fills.py:97-116` 的应用逻辑存在以下设计风险：

- BUY 直接扣现金，没有在提交前拒绝负现金；
- SELL 先增加现金，再检查是否持有；
- 超卖时可按完整卖出量增加现金，再把持仓删掉；
- 未持有标的虽然记录告警，但现金可能已经被增加。

这不是策略问题，而是账本正确性问题。建议未来实现时采用“先校验、后一次性提交”：

1. 所有成交先构建候选新状态；
2. 校验 `cash >= 0`；
3. 校验卖出数量不超过可卖数量；
4. 校验持仓数量不为负；
5. 校验同日重复应用；
6. 校验通过后原子写入 holdings、cash、fills 和 journal；
7. 任一校验失败则整批不落账。

### 4.3 P0：基准与组合缺日口径可能错配

`quant/ops/compute_nav.py:71-87` 在缺少上一交易日净值时，组合收益可能跨越多个自然交易日，但基准仍可能只计算一天。这会直接污染：

- 日超额；
- 累计超额；
- 年化超额；
- IR；
- 跟踪偏差。

已有实盘净值确实缺少若干交易日，因此日报中的累计超额不能直接作为验收依据。建议基准收益始终按“上一个实际 NAV 日期 → 当前 NAV 日期”计算，并为缺日序列增加 `period_start`、`period_end`。

### 4.4 P0：生产模型和信号版本未显式钉住

风险包括：

- `predict_daily` 按 MLflow 最新 recorder 选择生产模型；
- 同日信号已有 `.done` 时可能跳过重算；
- 模型升级后，当日订单可能仍使用旧信号；
- 未过门禁 recorder 依赖隔离纪律，历史上已经发生过顶替问题。

建议建立不可歧义的生产清单：

```text
production_manifest:
  model_id
  recorder_id
  feature_schema_hash
  training_cutoff
  universe_version
  data_version
  strategy_config_hash
  promoted_at
  approver
```

每个 signals/orders/fills 文件都携带该 manifest ID。模型、数据或配置变化时，同日信号必须判定失效，而不是只看文件是否存在。

### 4.5 P0：订单日不能静默回退到任意旧订单

`quant/ops/common.py:147-167` 在上一交易日没有订单时，会回退到更早的最近订单。这可以帮助断档恢复，但也可能把过期订单当成当日应执行订单。

建议：

- 正常生产模式：上一交易日缺单即 CRIT，中止；
- 明确的灾难恢复模式：必须人工指定 `--order-day`，记录恢复原因；
- orders 增加 `valid_for_trade_day` 和过期时间；
- 订单执行后写不可重复消费的 execution ID。

### 4.6 P1：数据契约声明强于实际约束

`quant/contracts/schemas.py:68-84` 会把非法数字转换为 NaN 或将非法整数填为 0，但转换后没有完整检查：

- 非空；
- 有限值；
- 正价格；
- 买入整手；
- 唯一键；
- 同一标的同方向重复；
- 金额与价格×数量一致。

此外，`make_trade_plan.py:439-447` 部分输出仍直接 `to_csv`，没有完全通过统一契约写入。

建议把契约分为三层：

1. **语法 schema**：列名和类型；
2. **业务 invariant**：现金、持仓、价格、数量、唯一键；
3. **状态 transition**：订单能否从 planned 进入 filled/applied/reconciled。

### 4.7 P1：涨跌停和交易制度模型不完整

- Backtrader 使用统一 9.5% 阈值；
- 日常规则对创业板/科创板与主板有所区分，但北交所口径仍不统一；
- ST 5% 涨跌停未完整建模；
- 退市整理期、上市初期无涨跌幅限制等特殊状态未覆盖。

这会影响可交易性、未成交率和复演结果。应以证券状态主数据而不是仅靠代码前缀判断。

### 4.8 P1：调度、核心链与建议链耦合

`run_daily evening` 会串行执行舆情记忆、短线猎手、大盘看板和板块预测。运行日志显示某些 evening 任务延续到次日凌晨，LLM 服务也出现连接拒绝、429 和 500。

建议拆成：

```text
核心交易链（有严格 SLA）
数据 → 质检 → 信号 → 组合 → 订单 → 风控确认

异步建议链（可延迟、可失败）
Agent → 舆情记忆 → 短线 → 看板 → 行业预测 → 报告
```

只有确定性的硬风险数据可以阻断订单；LLM 失败不得让核心订单延迟到次日，也不能静默改变执行含义。

### 4.9 P1：调度器与 Web 进程部署耦合

APScheduler 在 `webapp/server.py` 的应用生命周期中启动。风险包括：

- Web 重启影响交易调度；
- 多 worker 部署可能重复启动任务；
- API 手工触发与定时触发缺少全局互斥；
- 子进程普遍缺少统一超时、重试和幂等键。

建议将调度器独立为单实例 worker，Web 只读任务状态并提交带幂等键的任务。

### 4.10 P1：外网访问控制不应信任任意转发头

`webapp/server.py:82-91` 直接读取 `X-Forwarded-For`/`X-Real-IP`，再以 IP 白名单决定完整权限。如果 8000 端口可被公网直接访问，客户端可能伪造转发头。

建议未来部署时：

- 8000 仅监听 localhost 或内网；
- 只允许可信反向代理连接；
- 反向代理覆盖而不是透传客户端提供的转发头；
- 写操作使用身份认证、CSRF 防护和审计日志，不只依赖 IP；
- 只读演示也不公开真实账户持仓、净值和订单。

### 4.11 P1：核心执行层自动测试不足

现有 Agent 与 overlay 口径测试可运行通过，但缺少以下高价值测试：

- `make_trade_plan` 与 Qlib/Backtrader 选股一致性；
- 现金不足、超卖、重复成交、外部现金流；
- 缺日 NAV 与基准；
- 订单日过期与灾难恢复；
- ST/20%/30% 涨跌停；
- 部分成交、计划外成交和多次加减仓；
- 调度重复触发；
- 从信号到对账的 golden E2E。

本次执行内置测试结果：Agent 5 组、TA schema 和行业预测 schema 测试均通过；环境未安装 pytest，项目使用直接运行测试文件的方式。

### 4.12 当前新增行业预测模块

设计优点：

- LightGBM 生成数值，LLM 只后置解释；
- T+1 起算；
- 10/20 日双期限；
- 不直接修改订单；
- 有 shadow 门和到期结算。

当前不能进入资金决策，原因：

1. 历史面板使用当前池和当前行业映射回看，存在幸存者/分类时点偏差；
2. OOS 切分没有按 10/20 日标签做 purge/embargo；
3. 80 个 OOS 日存在重叠标签，名义样本量高于有效独立样本量；
4. up 组有简单对照，但 avoid 组没有独立、充分的门禁；
5. 只比较命中率差，没有置信区间和多重检验修正；
6. 线上正式预测尚未积累到期样本；
7. 模型产物位于运行目录，多环境可复现性不足。

建议继续保持 shadow，直到完成 PIT 重建和至少 60 个非重叠或经重叠修正的到期样本。

### 5.6 小资金 TopK7 的结构性问题

约 3 万元账户与 TopK50 无法等价：

- 100 股整手导致权重离散；
- 最低 5 元佣金抬高小单成本；
- 高价股买不起一手；
- 排除创业板/科创板改变信号分布；
- 7—12 只组合的特异风险明显更高；
- 行业约束因持仓少被关闭；
- UMP 否决后候选结构再次变化；
- 某一只未成交会显著改变组合。

必须单独回测/复演：

```text
资金：20k / 30k / 50k / 100k
持仓：6 / 8 / 10 / 15
每次替换：1
整手：100
最低佣金：5
真实板块权限
次日开盘价与滑点分布
部分成交和涨跌停
实际人工延迟
```

输出应比较“收益、回撤、费用率、现金率、集中度、未成交率”，不能只优化 IR。

### 5.7 现有短线猎手能否直接转成交易策略

不能。

现有 `swing_hunter` 预测“未来 10 日内收盘是否达到 +10%”，其历史 Phase 0 只证明 LGBM Top30 的自然 hit 率约高于随机池，并未证明按明确买卖规则交易后可以盈利。在线跟踪中，已结束预测整体表现偏弱，平均结算收益为负。

现有设计还有四个交易化缺口：

1. `strict` 无预测时会降为 `standard`，这会为了“必须出结果”而降低质量；
2. 目标是“期间是否碰到 +10%”，不是可成交、可复现的退出规则；
3. 主要基于日线与 LLM，缺少集合竞价、分钟量价、VWAP、封单变化和排队成交数据；
4. 当前 10:00 盘中快照适合展示，不足以回放 9:25—10:00 的入场决策。

因此建议保留 swing_hunter 作为**候选生成器和研究标签器**，交易策略必须另建确定性规则、独立账户和独立回测。

### 5.8 30k 短线涨停策略专项设计蓝图

> **09-10 状态：本节降为研究 challenger，不再是真钱主路径。**  
> 真钱 30k 主账本按 §0 / §5.10 的 60 日票组运行。  
> 本节仍保留：若未来要做 2—10 日涨停后续，必须用独立 `short_limit_shadow` 账户，不得写入 30k 周期票组。  
> **本节不是当前系统已经生成的筛选结果。** 当前系统尚不存在把这些模块统一汇总并输出 `short_limit_30k` 订单的生产策略。

当前系统已有能力与本节设计的关系：

| 现有模块 | 当前产出 | 在短线策略中的正确定位 |
|---|---|---|
| Alpha158/LGBM | CSI500 横截面分数 | 候选弱特征，不能直接作为涨停买点 |
| `market_board` | 首板、连板、炸板、情绪周期、封单快照 | 市场状态和涨停结构特征源 |
| `swing_hunter` | 5—15 日 +10% 的 LLM 建议 | 候选研究和风险摘要，不直接出订单 |
| `sector_forecast` | 10/20 日行业相对强弱 | 背景证据，不决定短线入场 |
| 舆情模块 | 公告、事件和硬伤提示 | 事实核验/否决，不生成收益概率 |
| `execution`/`ops` | 订单、成交、对账、净值 | 复用基础设施，但必须使用独立策略和账户 |

#### 5.8.0 在整体 L0—L5 架构中的位置

短线涨停策略不应继续作为一个只读 overlay 堆叠到 `swing_hunter` 中。只要它能够影响真钱订单，它就是一条完整的生产策略线，必须经过研究、验证、执行和运维各层：

```text
L0 数据层
  PIT 日线 + 分钟线 + 集合竞价 + 涨跌停状态 + 历史题材/公告
        ↓
L2 短线研究层（独立于 Alpha158 基线）
  T日首板候选 → 硬过滤 → 确定性排序 → short_candidates
        ↓
L3 短线验证层
  T+1 可成交入场 + T+1限制 + 炸板/跌停 + 整手 + 最低佣金 + 滑点
        ↓
L4 组合与执行层
  30k风险预算 → 3k下限/6k上限 → short_orders → 人工成交回填
        ↓
L5 运维与归因层
  独立账户 → 对账 → NAV → 逐笔期望 → 回撤/停机 → 看板

Overlay / Agent 旁路
  LLM舆情、行业预测、市场解释
  只能提供证据或硬伤提示，不能绕过 L2/L3 直接写订单
```

建议的代码职责边界（仅为未来架构建议，本次不修改代码）：

| 层 | 建议职责 | 不应承担的职责 |
|---|---|---|
| `data_pipeline` | 保存可回放的分钟/竞价/PIT 事件数据 | 选股和调仓 |
| `research/short_limit` | 候选、特征、标签、确定性评分 | 真实账户记账 |
| `validation/short_limit` | 事件驱动回测、成本和成交压力测试 | 修改生产模型 |
| `execution` | 通用资金约束、订单状态机、成交应用 | 临时改变候选排名 |
| `ops` | 分阶段调度、互斥、审计和告警 | LLM 选股 |
| `overlays` | 舆情、行业、市场解释 | 直接生成真钱订单 |

新的短线数据契约不能复用当前只有 `instrument, score, rank` 的普通信号而不加语义。至少需要：

```text
strategy_id
signal_day
valid_trade_day
instrument
setup_type
entry_window
max_entry_price
invalidation_rule
target_amount
expires_at
model_or_rule_version
data_version
```

所有候选、信号、订单、成交和 NAV 都要携带同一个 `strategy_id=short_limit_30k`，防止与指数增强、人工持仓或 ETF 混账。

短线策略还需要独立于当前 evening/postclose 的交易时序：

```text
T日 15:10后   固化首板/炸板/板块数据，生成次日观察名单
T+1 09:25     读取集合竞价，执行硬过滤
T+1 09:35~10:00  生成有效期很短的入场指令；人工确认/限价执行
T+1 收盘      记录当日不可卖的风险状态
T+2起         按退出规则处理；跌停未成交继续保留风险
每日收盘      对账、逐笔归因、更新回撤和停机状态
```

所谓“整体系统筛选”不应是多个模块投票。正确的决策权顺序应是：

```text
数据完整性门 → 交易权限/可成交性门 → 市场状态门
→ 短线策略确定性评分 → 账户风险预算 → 订单
```

LGBM、行业预测、舆情和 LLM 可以作为输入证据，但不得各自越权下单，也不得在没有历史验证时通过“多数意见一致”放大仓位。

#### 5.8.1 先定义做哪一种“涨停策略”

涨停策略至少有三种，风险和数据要求完全不同：

| 类型 | 入场 | 优点 | 主要问题 | 当前建议 |
|---|---|---|---|---|
| 封板打板 | T 日接近涨停时排队买入 | 最贴近“打板” | 买到与否取决于队列；开板时逆向选择严重 | 暂不做 |
| 首板次日竞价 | T 日首板，T+1 集合竞价/开盘买 | 规则清晰 | 高开回落、隔夜消息、开盘滑点 | 可研究 |
| 首板次日确认 | T 日首板，T+1 9:35—10:00 确认承接后买 | 可过滤弱票 | 需要分钟数据；成交更晚、价格更高 | **优先方向** |

以当前系统能力，最合适的不是“封板排队”，而是**首板后次日换手确认/回踩承接**。原因是封死的好板通常买不到，容易买到的开板票往往包含更高失败风险；如果历史回测假设所有封板单都能成交，会产生严重虚假收益。

#### 5.8.2 策略目标

- 持有期：2—5 个交易日为主，最长不超过 10 日；
- 收益目标：优化**成本后每笔期望值**，不是优化“碰到涨停的次数”；
- 交易频率：没有合格信号时持有现金；
- 宇宙：先限定有权限的沪深主板、非 ST、非退市整理、非上市初期特殊规则标的；
- 账户：独立 `short_limit_30k` 研究/实盘账本，不混入当前指数增强账户；
- LLM：只解释事件和提示硬伤，不生成分数、不改变确定性交易规则。

#### 5.8.3 T 日候选规则

以下是应进入网格回测的候选规则，不是未经验证就直接上线的参数：

1. **首板优先**：过去 20 个交易日无涨停，当日首次收盘封板；
2. **排除一字板**：T 日必须有真实换手，避免假设不可成交；
3. **排除高位连板**：初版不做 3 板及以上接力；
4. **流动性门槛**：20 日平均成交额和当日成交额达到可执行标准；
5. **换手质量**：成交量相对 20 日均量放大，但排除极端爆量出货；
6. **板块共振**：同题材/行业有多只涨停或上涨扩散，而不是单票孤立；
7. **市场状态**：退潮、高炸板率、跌停扩散时停止开新仓；
8. **事件真实性**：公告和催化必须可追溯；LLM 只能标注，最终硬规则由代码判断；
9. **价格可买性**：按 100 股整手和单票上限计算后，实际投入必须落入允许区间；
10. **避免已知硬伤**：ST、立案、重大减持、债务危机等进入人工确认或确定性禁买。

现有 `market_board` 已能提供首板、一字板、T 字板、换手板、炸板率、连板高度和市场周期，可作为候选特征来源；但历史行业/题材和公告必须按当时可见信息保存，不能用今天的分类回看过去。

#### 5.8.4 T+1 入场规则

建议同时验证两个版本：

**版本 A：日线可复现基线**

- T 日收盘确定候选；
- T+1 开盘涨幅落在待验证区间（例如 -2% 至 +4% 的参数网格）；
- 开盘未涨停、未停牌；
- 按 T+1 开盘价加真实滑点成交；
- 高开过大、直接一字涨停或低开失效则不买。

优点是当前日线数据可以回测；缺点是无法判断 9:30 后承接。

**版本 B：分钟级确认版**

- 9:25 集合竞价后不立即追单；
- 9:35—10:00 观察开盘涨幅、成交额、VWAP、首 15 分钟高低点和板块同步；
- 价格重新站上 VWAP/关键价且成交额确认后入场；
- 跌破失效位、板块快速退潮或炸板率恶化则取消；
- 订单使用限价并记录未成交，不得回测成必然成交。

版本 B 必须先保存 1 分钟行情、集合竞价快照和实际下单时间，当前单次 10:00 快照不足以支持可信回测。

#### 5.8.5 退出规则

A 股 T+1 意味着买入当日不能卖出，短线策略最大的风险发生在“买入后当天走弱但无法退出”。退出必须按可成交时点建模：

1. **最早退出**：T+2；
2. **失效退出**：前收盘或盘中触发风险线后，在下一可交易时点执行；
3. **时间退出**：第 3/5/8 日做网格比较，避免无 Alpha 持仓拖长；
4. **盈利退出**：比较固定目标、分批止盈和回撤跟踪三种方式；
5. **涨停持有**：再次封板不能自动等同于次日继续持有，应结合市场周期；
6. **跌停无法卖出**：风险继续计入，不得在回测中按止损价成交；
7. **尾盘规则**：任何使用收盘条件的策略，都必须在下一交易日成交，不能用同一收盘价退出。

初始研究网格可覆盖：

```text
风险线：-4% / -5% / -6% / 波动调整
目标收益：+6% / +8% / +10%
最长持有：3 / 5 / 8 日
入场高开范围：[-3%, +2%] / [-2%, +4%] / [0%, +5%]
```

不能看到哪个组合历史收益最高就直接采用，应选择跨年份、跨市场状态都稳定的参数区域。

#### 5.8.6 30,000 元资金和单票 3,000 元约束

单票 3,000 元应定义为**实际成交金额下限**，不是预算标签：

```text
shares = floor(target_amount / (price × 100)) × 100
actual_amount = shares × price
仅当 actual_amount ≥ 3,000 元时允许下单
```

推荐的初始资金结构：

| 项目 | 金额/数量 | 说明 |
|---|---:|---|
| 总资金 | 30,000 元 | 独立短线账户 |
| 现金缓冲 | 6,000 元（20%） | T+1、滑点、补单和极端行情缓冲 |
| 常规部署 | 24,000 元 | 不要求每天满仓 |
| 目标持仓 | 5 只左右 | 每只目标约 4,800 元 |
| 单票硬下限 | 3,000 元 | 低于即跳过 |
| 单票常规区间 | 4,500—5,000 元 | 比 3,000 元更能摊薄最低佣金 |
| 单票硬上限 | 6,000 元（20%） | 5 只高度相关时账户风险仍高 |
| 同题材上限 | 2 只或 30% | 防止同一情绪链同时失效 |
| 新开仓/日 | 1—2 只 | 降低同日追高和人工压力 |

如果 100 股一手已经超过 6,000 元，即股价高于约 60 元，初版直接跳过；如果按目标金额取整后不足 3,000 元，则增加到满足下限的整手数，但不得突破 6,000 元上限。

“最多 10 只×3,000 元”虽然数学上可满仓，但并不推荐：10 只会带来更多最低佣金、更多人工执行和更弱的候选质量。5 只左右、允许持有现金，更符合短线精选逻辑。

#### 5.8.7 成本门槛

按项目当前费率，3,000 元单票完成一次买卖：

- 买卖最低佣金约 10 元；
- 卖出印花税约 1.5 元；
- 固定税费约占 0.383%；
- 若买卖各有 0.1% 滑点，往返成本约 0.58%；
- 若买卖各有 0.2% 滑点，往返成本约 0.78%；
- 尚未包含高开、跌停无法退出和人工延迟造成的尾部损失。

4,800 元单票的固定佣金拖累更低，叠加 0.1%—0.2% 双边滑点后，往返成本约 0.46%—0.66%。因此 3,000 元是合理硬下限，但不应成为常规目标金额。

若平均盈利 8%、平均亏损 5%、往返成本 0.8%，盈亏平衡胜率约为：

`(5% + 0.8%) / (8% + 5%) ≈ 44.6%`

若跳空使平均亏损扩大到 8%，盈亏平衡胜率会升到约 55%。所以短线策略不能只看 hit rate，必须同时看平均盈利、平均亏损和尾部跳空。

#### 5.8.8 市场状态与停手机制

短线涨停策略高度依赖市场情绪。建议把现有大盘周期用于**仓位门控**而不是直接选股：

| 状态 | 新仓建议 |
|---|---|
| 回暖 | 正常候选，最多 1—2 笔 |
| 高潮早期 | 降低追高，优先低位首板 |
| 高潮末期 | 减少新仓，防止次日分歧 |
| 退潮 | 禁止新仓，只处理退出 |
| 冰点 | 观察反转，不因“跌得多”自动抄底 |

账户级候选停机规则：

- 连续 3 笔止损：暂停新仓 2 个交易日并复核；
- 滚动 20 笔成本后期望值 ≤0：切回 shadow；
- 从高点回撤 6%：仓位减半；
- 回撤 10%：停止实盘，独立复核；
- 当日数据、分钟行情或订单状态不完整：不交易。

这些数值是待验证的风险授权建议，不是盈利保证。

#### 5.8.9 排名与决策结构

推荐采用确定性两阶段结构：

1. **硬过滤**：权限、ST、流动性、首板、一字板、价格可买性、市场退潮；
2. **排序**：板块共振、封板质量、成交额、换手、相对强度、催化可信度；
3. **人工确认**：只确认事实和执行条件，不临时改模型；
4. **LLM**：输出风险摘要，不产生买入概率和仓位。

现有 LGBM Top30 只能作为一个弱特征，因为其历史 +10% hit 率相对随机的优势不大，且目标标签是 5 日收益而不是首板次日收益。

#### 5.8.10 验证门禁

上线前至少满足：

- 历史样本不少于 200 笔可成交交易；
- 按年份、牛熊、回暖/退潮分层后不依赖单一阶段；
- purged walk-forward，最终测试期不参与调参；
- 所有收益扣除最低佣金、印花税、实际滑点；
- 封板排队未成交、涨跌停无法退出按现实处理；
- 成本后平均每笔收益 >0，95% 置信区间尽量不跨 0；
- Profit Factor 建议 ≥1.3；
- 最大回撤建议 ≤10%—12%；
- 单笔期望至少达到估计往返成本的 2 倍；
- shadow 至少 60 笔已结算信号；
- 真实小仓至少 20—30 笔且零未解释对账差异。

### 5.9 行业预测

当前 OOS 报告的 10 日/20 日命中率优于“追涨 Top3”，但平均超额仅约 0.26%/0.02%，且存在重叠标签、PIT 和门禁不完整问题。这些结果不足以覆盖交易成本，也不足以分配资金。

建议其当前定位为：

- 市场状态/风险提示；
- 组合暴露解释；
- shadow 预测；
- 不做个股订单加权；
- 不作为强制行业轮动。
- 09-10 起：可作为 T0 CaseFile 的背景字段，不得单独决定是否进票组。

### 5.10 双线同一方案：60 日票组如何选、如何调、如何结束

> 这是 09-10 授权的**两条线共同操作说明书**，不是回测结论。第一个周期在账本 P0 未修完时，只允许「遗产隔离 + 按清单建组」，不允许把成绩单写成策略已验证。

#### 5.10.1 两条线只允许这些不同

| | 研究线 100k | 真钱线 30k |
|---|---|---|
| 策略、票组、只数、日历、失效条件 | 相同 | 相同 |
| 资金 | 100,000 模拟 | 30,000 真实 |
| T0 / 现金 | 约 67k / 33k | 约 20k / 10k |
| 成交 | 次日开盘模拟 | 人工 |
| 第一成功指标 | 同周期成本后 TWR + 与真钱的执行偏差 | 同周期成本后 TWR、对账、人工偏离 |

研究线赢了不能证明真钱；真钱赢了若研究线同票组亏损，先查执行再谈 Alpha。成长只使用「按规则成交」部分；人工偏离只进执行诊断。

#### 5.10.2 T0 如何「根据每个票的分析」生成票组

推荐决策权顺序（与 AutoHedge 委员会同构，但数字由代码/账本出）：

```text
数据完整性 → 交易权限/可买性（整手后 ≥3,000）→ 硬伤否决
→ 模型/规则分数（LGBM 等，不由 LLM 改写）
→ CaseFile 摘要（研究辩论、舆情、板块，只提供证据）
→ 按各线 2/3 资金等权（或 Mandate 规定的权重）
→ 同一清单：研究线模拟下单，真钱人工确认后下单
```

票组规模建议（两条线相同）：

- 目标 4—5 只；T0 最多 6 只（由 30k × 2/3 / 3,000 约束）；
- 不得为了凑只数把任一线的单票压到 3,000 以下；
- 30k 上买不起或一手超过该线 20% 上限的票，两条线都跳过；
- 同期题材/行业高度相关时限 2 只或约 30% 资金。

#### 5.10.3 第一个月如何「根据行情调整票组」

允许的调整（必须有原因代码，**两条线同一名单**）：

1. **失效退出**：进组时写明的失效条件被触发（硬伤、破位、停牌、权限变化）；
2. **替补替换**：只能来自 T0 已分析、当时未买进的候补名单，或本周完成同等 CaseFile 的新票；
3. **减仓保护**：单票触及预先授权的风险线后，下一可卖时点减仓。

不允许的调整：

- 看见涨停/热门板块就临时新开清单外标的；
- 把剩余 1/3 现金一次性打满「免得踏空」；
- 为了抬高当月收益率降低单票到 3k 以下或加到无上限；
- 只在真钱调、研究线不调（或反过来）——那会把执行差伪装成策略差。

#### 5.10.4 剩余 1/3 如何逐步投入

- 默认窗口：第一个月结束后、周期结束前；
- 只加仓仍有效的当期持仓，或已批准替补；
- 每笔加仓后该票总额建议 ≤ 该线总资金 20%；
- 若票组已失效、市场状态不满足 Mandate，现金可以一直持有到 T_end；
- 逐步投入的路径必须在 T0 Mandate 里写好，周期中不得改成「今天全买」。

#### 5.10.5 满 2 月如何「再来初始」

「再来初始」不是把历史 NAV 清零假装没亏过，而是：

1. 两条线同一天冻结本期持仓与现金，各算周期 TWR 与归因；
2. 决定每只票 **继承 / 减仓 / 清仓**（名单相同）；
3. 用新 Mandate 生成下一期票组；
4. 需要的卖出与买入作为**新周期 T0 交易**记录，而不是改写上期成交；
5. 注资、撤资、ETF、遗产持仓继续留在 external 账本。

若上期亏损，下一期仍按各线总资金的 2/3 + 1/3 出发，而不是为了回本取消现金缓冲。

#### 5.10.6 与「每月 +10%」同时成立的风控

即使 stretch 目标是月 +10%，周期内仍建议保留（待验证的授权，不是承诺）：

- 周期最大回撤触及 10%：停止 M2 加仓，只处理退出（两条线同时）；
- 单日亏损触发现有 3% 熔断：当日不再买入；
- 连续两期成本后 TWR 为负：下一期强制降低 T0 部署比例，先修规则；
- 对账未解释差异：禁止开新周期。

这些与 stretch 目标冲突时，**以风控和账本为准**。

## 6. 专业角色设计

项目由一人运行时，也应在流程上扮演相互制衡的不同角色，不能在同一次操作中混用权限。

| 角色 | 核心职责 | 不能做什么 | 关键产物 |
|---|---|---|---|
| CIO/投资负责人 | 目标收益、最大可承受回撤、资金分配 | 不直接挑单日股票 | 投资授权书 |
| 组合经理 PM | 组合、风险预算、策略权重 | 不修改历史测试结果 | 组合决策单 |
| 量化研究员 | 因子、模型、标签、假设 | 不批准自己的最终测试 | 研究报告 |
| 独立验证/MRM | 冻结数据、walk-forward、压力测试 | 不参与参数搜索 | 验证意见 |
| 数据负责人 | PIT、复权、成分、公司行动 | 不根据收益挑数据版本 | 数据版本报告 |
| 交易员 | 按批准订单执行、记录偏差 | 不无记录地改变组合 | 执行日志 |
| 风控负责人 | 限额、熔断、叫停、异常复核 | 不追求短期收益最大化 | 风险日报 |
| 绩效归因 | 拆解 Alpha、Beta、现金、人工、费用 | 不把注资计入收益 | 月度归因 |
| SRE/运维 | 调度、备份、恢复、告警 | 不决定买卖方向 | SLA 报告 |

### 6.1 单人项目的最小隔离办法

1. 周末只以“研究员”身份提出候选与 CaseFile；
2. 至少隔一天，以“验证员”身份按固定模板审查 Mandate；
3. 测试集一旦打开就不得重新调参；同一 60 日周期内不得既交易又改门槛；
4. 上线 / 开新周期需要单独签署 manifest；
5. 交易日只以“交易员”身份执行已批准票组清单；
6. 人工偏离必须选原因代码；
7. 周期结束才以“PM”身份调整下一期规则；月中不以冲 +10% 为由改 Mandate；
8. 风控叫停不能由同一笔交易冲动即时解除。

## 7. 盈利导向的策略与组合框架

### 7.1 双线资金预算（同一方案，按资金缩放）

以下是研究与治理框架，不是直接下单建议。原「12k→24k 短线满仓阶梯」和「研究 TopK50 vs 真钱浓缩」都被同一周期票组替代。

两条线共用一张阶段表，金额按 100k / 30k 缩放（约 10 : 3）：

| 阶段 | 研究线部署 / 现金 | 真钱线部署 / 现金 | 进入下一阶段 |
|---|---|---|---|
| 账本重置 | 0 / 100,000 | 0 / 30,000 | 子账本拆开、遗产打标 |
| 周期 T0 | 约 67,000 / 33,000 | 约 20,000 / 10,000 | 同一票组；单票成交 ≥3,000 |
| 周期 M1 | 仍约 2/3，可按同一名单换票 | 同左比例 | 调整均有原因代码 |
| 周期 M2 | 最多加到满资金 | 同左比例 | 只加有效持仓/替补；单票 ≤ 该线 20% |
| 周期结束 | 按新 Mandate 重建，再留约 1/3 现金 | 同左 | 两份成绩单都完整 |

TA、行业预测和 LLM 舆情当前均不获得独立资金预算。短线涨停若试验，必须另开第三条 shadow，不占用上表。

### 7.2 不建议立即照搬的退出参数

单票止损、止盈和组合降仓可能有帮助，但任何固定数字都会改变策略分布，必须先回测。建议研究以下候选，而不是直接上线：

1. **信号失效退出**：首板次日结构失败；
2. **波动调整风险退出**：基于 ATR/20 日波动，而不是所有股票同一百分比；
3. **时间退出**：持有 3—8 日后短线动能未兑现；
4. **盈利保护**：达到一定盈利后使用回撤式退出；
5. **组合回撤降仓**：分层降低风险，而不是一次清仓；
6. **市场状态降仓**：必须独立验证，不能看到大跌后临时加规则；
7. **涨跌停延续状态**：不能把无法卖出的订单当作已经完成风险退出。

### 7.3 风险预算比单一止损更重要

建议未来组合构建从“只按排名等权”升级为受约束风险预算：

- 单票目标和硬上限；
- 行业上限；
- 风格暴露上限；
- 组合预期波动；
- 单日可成交金额；
- ADV 参与率；
- 预期交易成本；
- 现金缓冲；
- 未成交后的替代策略；
- 当前回撤状态。

## 8. 立即行动项与 90 天路线

### 8.1 P0：立即止血（第 0—2 周）

1. 停止用当前实盘 IR、年化超额或累计超额证明策略有效，也停止把「每月 +10%」写成可保证。
2. 冻结新增会影响订单的策略功能；分析 overlay 继续旁路。
3. 将系统持仓、人工持仓、ETF 和外部资产拆账；09-03 等非 fills 注入打永久审计标签。
4. 修正缺日基准口径，并重算全部日报。
5. 建立现金非负、禁止超卖、禁止重复应用、**单票实际成交 ≥ 3,000** 等硬不变量。
6. 缺上一交易日订单时停止静默回退。
7. 核心交易链与 LLM/看板任务拆开。
8. 确认公网 8000 端口的访问控制和转发头信任边界。
9. 备份当前所有运行数据和模型 manifest。
10. 两条线配置都改到同一周期方案（当前研究仍是 TopK50、真钱仍是 20k/TopK7，与授权不一致；本次审查仍不改代码）。

### 8.2 P1：第一条 60 日周期（第 2—10 周，两条线同时）

1. 写出 Cycle-1 Mandate：宇宙、禁止项、失效条件、M2 加仓路径、回撤停机。
2. 对候选逐票 CaseFile，生成 **一份** 4—5 只票组。
3. T0：研究线按约 67k/33k 模拟买入，真钱约 20k/10k 人工买入；任一线整手后不足 3,000 则该票两条线都不进组。
4. M1 只做清单内调整，且两条线同一名单；1/3 现金不得因「踏空」提前打满。
5. M2 按 Mandate 逐步加仓；不合格持现。
6. 真钱全程人工下单、当日回填、对账；未解释差异则两条线都暂停加仓。
7. 周末只对比执行偏差（未成交、滑点、延迟），不得把研究线改回 TopK50。
8. 周期结束两份成绩单（§0.5），再决定 Cycle-2 是否继承持仓。
9. 短线涨停模块如需试验，另开第三条 shadow，不写入 Cycle-1。
10. 建立按票、按决策类型（T0 / M1 / M2）的费用与滑点归因，并分列「规则内 vs 人工偏离」。

### 8.3 P1：前向运营验收（第 6—12 周，与 Cycle-1 重叠）

至少一个完整周期结束，同时满足：

- 数据日完整、订单日明确；
- 对账无未解释差异；
- 无策略外持仓混入 `system_model_book`；
- 研究线与真钱为同一票组、同一只数（仅资金与成交方式不同）；
- 资金流正确剥离；
- 实际费用完整；
- 单票实际成交额不低于 3,000 元；
- 没有合格加仓点时允许现金；
- 手工偏离率受控并带原因代码；
- 周期最大回撤未超授权；
- 月度 +10% **不是**本阶段毕业条件，只作为成绩单上的观察列。

未达标则延长观察或降低下一期 T0 部署比例，不因某周盈利而提前打满剩余现金。

### 8.4 P2：成长与扩展（90 天 / 至少两期周期以后）

只有两期成绩单可复盘后：

1. 用周期归因决定下一期 Mandate（因子、行业约束、失效规则），禁止用同一期数据调参后再宣称样本外；
2. 用两线执行偏差决定是否先修成交/权限/整手，而不是先改选股；
3. 行业预测 / TA / 短线分别作为 challenger，不能共享主策略测试集；
4. 若连续两期总 NAV 成本后 TWR 为负，先降仓与修执行，不加模块；
5. miniQMT 自动化必须先通过仿真、断线、重复单和撤单演练；真钱默认仍手动；
6. 扩仓依据容量和回撤预算，而不是最近是否碰到 +10% 的月份。

## 9. 上线与扩仓门禁

### 9.1 模型门禁

- 数据和成分为 point-in-time；
- 训练、验证、最终测试职责分离；
- 标签期限对应 purge/embargo；
- 多次尝试已披露；
- 新模型在多个市场状态下稳定；
- 成本压力测试后仍有正期望；
- 模型 ID、数据版本和配置哈希固定；
- challenger 不自动覆盖 champion。

### 9.2 执行门禁

- 订单、成交、持仓和现金可双向重建；
- 现金永不为负；
- 禁止超卖；
- 重复应用无副作用；
- 对账差异必须解释；
- 真实费用入账；
- 未成交和部分成交有状态；
- 过期订单不可消费；
- 人工偏离可归因；
- 灾难恢复经过演练。

### 9.3 扩仓 / 开下一周期门禁

- 上一周期成绩单完整（§0.5）；
- 无未解释对账差异；
- 单票实际成交 ≥ 3,000 元；
- 策略外资产已拆账；
- 实际费用与滑点已入账；
- 研究线与真钱为同一票组；两线收益差只解释为执行差距，不单独改下一期选股；
- 月度是否达到 +10% **不作为**开门条件；
- 连续两期亏损则降低下一期 T0 部署；
- 由“验证员”和“风控负责人”两个流程共同批准下一期 Mandate。

## 12. 最终建议

09-08：项目应从“功能快速扩张期”切换到“投资生产系统硬化期”。09-10 补充：硬化之后两条线跑**同一 60 日票组方案**，研究 100k 模拟、真钱 30k 手动。

最优先的四件事是：

1. **让每一元盈亏都能归因**；
2. **让研究线与真钱运行同一策略、同一票组**（只允许资金和成交方式不同）；
3. **让最终测试真正未被调参触碰**；
4. **让任何账本错误都无法静默发生**。

针对 09-10 运营授权：

- 策略和方案相同：1—2 月重建票组，T0 买约 2/3、留约 1/3，M1 只调失效，随后逐步投入，满约 2 个月结算再建；
- 研究线 100,000 元模拟；真钱 30,000 元人工；
- 单票实际成交不低于 3,000 元；只数以 30k 能买得起的为准，两条线相同；
- 每月 +10% 记为 stretch 目标：成绩单分列总 NAV 与已投资本金；**系统不保证该目标**；
- 短线涨停蓝图保留为独立第三条线，不写入这两条主账本。

这不表示策略已经可用。第一个周期的成功标准是干净账本与可复盘成绩单。如果跳过拆账和对账、用 LLM 选股直接下单、或为了冲 +10% 取消现金与单票下限，只会把执行错误放大成「策略失效」的假象。
